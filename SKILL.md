# TopicDock (`td`) — Cross-Client Topic Memory

Zero dependencies (Python >= 3.9, standard library only). The only distributable executable form is the single-file `scripts/topicdock.py` (alias `td`).
Syntax specification: `references/markdown-spec.md`; the 11 subcommands and their JSON payload/output contracts: `references/cli-contract.md`.

## Resident Wakeup Rules (3 lines, valid for the whole session, still binding after context compaction)

- **TopicDock Read (Mount)**: Only when starting a session's first substantive topic, when explicitly named (`continue <id|index>` / `继续 <id|序号>` / `/topicdock`), or when switching mid-session to an **unmounted new topic**, load the `topicdock` skill and call `td use [<id|index>] [--trace auto]` or `td match [--topic <kw>... | --recent] [--trace auto]`. Top-5 `td match` hits (`full: true`) already return `head_hop`, full 64-hex `base_sha`, `text`, and `artifacts` — **mount directly in 1 round without a redundant `td use` call** (call `td use <id>` only if the target ranked >=6 with `full: false`, or after context compaction / agent-role switch using the previous reply's trailing `⚓ TopicDock: <id> (<head_hop>@<sha6>)`). Once mounted in the same session and role, continue conversing with **0 redundant DB lookups**. Always batch `td` read/trace calls in parallel with workspace `read`/`grep`/`glob` tools in the same turn and deliver the substantive reply in that same turn.
- **TopicDock Trace (Lineage)**: Whenever (1) the user questions, overturns, or digs into any mounted `[C]`, `[R]`, `[Q]`, or `[A]` item (including folded, overturned, or merged items); (2) taking over unresolved `[Q]` or breakpoint `[~][A]` across sessions/roles (if not already inlined via `--trace auto`); or (3) deepening design or coding on existing `[C]`/`[R]` where top-level one-line summaries do not settle boundary details, call `td trace <topic_id> <item_id> [<item_id2>...]` (batching multiple items in one call, e.g. `C3,C4,Q3`) to pull full historical `hop-NNN.md` evidence blocks — never guess history from top-level summaries.
- **TopicDock Write (Distill)**: Only the **top-level primary Agent** (Subagents MUST NEVER call `td`; users MUST NEVER edit Markdown files manually) must immediately call `td save` **in the same turn before replying** (never ask "shall I save/hand off?" and wait an extra turn) upon hitting any of the 4 natural convergence nodes: (1) reaching or overturning a `[C]`/`[R]` conclusion; (2) surfacing an open question `[Q]` needing user or next-stage/role confirmation; (3) completing `[x]` or pausing at a handoff breakpoint `[~]` on an `[A]` stage; or (4) topic switch or wrap-up. Default to `--amend` for subsequent increments in the same session and `actor`; omit `--amend` across sessions or after switching `actor` to create the next hop; and echo `⚓ TopicDock: <topic-id> (<head_hop>@<base_sha[:6]>)` at the end of the reply.

## Workflow Contract

### Mount timing (Read)
- Call `td use` / `td match` only when the session's first substantive topic opens, the user names a topic (`continue <id|index>` / `继续 <id|序号>` / `/topicdock`), or the user switches mid-session to an **unmounted new topic**; a mounted topic continues conversationally in later turns of the same session and role with 0 redundant DB lookups.
- `td match` (decompose the user's topic into keywords/synonyms first): top <=5 hits (`full: true`) already return `text` + `head_hop` + full 64-hex `base_sha` + `artifacts` — mounting is complete in this single call; **never issue a second `td use` round**. Call `td use <id>` only when the target ranks >=6 (`full: false`). Pure time references (e.g. "continue what we discussed") need no `--topic`: call `td match --recent`, which returns the <=5 most recent topics sorted like `list` / `use` (`updated_at` DESC, `topic_id` ASC).
- When unresolved `[Q]` / breakpoint `[~][A]` history is needed, pass `--trace auto` (or a comma-separated item list such as `C3,C4,Q3`) to the same `td use` / `td match` call instead of issuing a separate `td trace` round.
- After context compaction (Compaction) loses the mounted `topics/<id>.md` body, or when a role switch within the same session requires the full 64-hex `base_sha`, re-call `td use <id>` once using the ⚓ line at the end of the previous message to refresh the full ledger and credentials.
- `td use` without a selector: 0 topics → guide onboarding; exactly 1 → direct mount; >=2 → show the first page of the list (columns: index | title | id | updated_at; natural-language hints below the list: reply with an index to mount / reply `删 <序号>` to request deletion, which triggers a `--dry-run` preview and only executes after you confirm with the explicit `topic_id` / next page or all / keyword filtering; consolidation is never a list-level operation and no CLI syntax is exposed).

### Trace timing (Lineage)
- Trace first when any of the three triggers hits: (1) the user questions, overturns, or digs into a mounted item's original evidence and reasoning (`[C]`/`[R]`/`[Q]`/`[A]`, including folded/overturned/consolidated items); (2) taking over unresolved `[Q]` or breakpoint `[~][A]` across sessions/roles, which requires the multi-line `推导与权衡` and `核心证据` fields from earlier hops; (3) deepening design or coding on existing `[C]`/`[R]` while top-level one-line summaries do not settle boundary details.
- On a hit, call `td trace <topic_id> <item_id> [<item_id2>...]` first and pull the full `hop-NNN.md` evidence blocks before answering; batch multiple items in one call (comma or space separated, e.g. `C3,C4,Q3`); never guess history from a top-level trailing one-line summary.

### Distill timing (Write)
- On hitting any of the 4 natural convergence nodes, call `td save` immediately in the same turn before replying — never ask "shall I hand off/save?" and wait another turn: (1) reaching/overturning a `[C]/[R]` conclusion; (2) an open question `[Q]` needing user confirmation or sign-off by the next session/stage/role; (3) an `[A]` stage completing `[x]` or pausing at a natural handoff breakpoint `[~]`; (4) topic switch or wrap-up.
- Subsequent increments in the same session with the same `actor` default to `--amend` (in-place update of the current hop); across sessions or after switching `actor`, omit `--amend` to create the next hop automatically (a sealed hop or session mismatch also auto-degrades to a new hop — no intervention needed).
- After a successful save, echo the ⚓ line at the end of the reply: `⚓ TopicDock: <id> (<head_hop>@<base_sha[:6]>)` (the `echo` field of the JSON output is the authoritative source of this line; the full 64-hex `base_sha` must be copied from the JSON `base_sha` field — never truncated or hand-assembled).
- `td save` is the only authoritative write entry (`--stdin | --json-file <path>`, optional `--amend / --fork-as <new_id> / --force-merge`); `td merge` is the single exception entry (cross-topic consolidation).
- **`next_focus` universal format**: describe the task, not the person — one self-contained sentence naming the next hop's first step (e.g. `"围绕 [Q1] 确认 hop model 字段在 v1 下的兼容策略，随后推进 [A2] 编写实现计划"`); only append a suggested role at the end when the host is multi-role and a clear division of labor exists.
- **`actor` and `model` attribution**: `actor` is the `<client>` (e.g. `claude-code`, `cursor`, `codex`) or `<client>/<role>` (e.g. `opencode/architect`), never a `@<model>` suffix; when the current model identifier is known, put it in the optional top-level `"model"` field (e.g. `"opencode-go/gemini-4-argon"`); omit `"model"` when unknown.

### Distillation standard: five-must-collect / four-not-collect
**Five must-collect (guarantee zero effective context loss across window/Agent switches)**:
1. **Settled conclusions and their concrete spec sub-items → `[C]`**: `statement + basis` must be high-density and self-contained (write out the concrete spec points; no hollow titles); multi-sub-item details and trade-offs go into the hop block `rationale` (推导与权衡).
2. **Verified objective facts and code/constraint baselines → `[C] (verified)` or `evidence_detail`**: key source paths/line numbers, existing interface contracts, experiment/benchmark data, and hard constraints clarified in the session must land as `verified` facts or the item's `evidence_detail` (核心证据), saving the next session from re-reading code.
3. **Rejected/overturned alternatives and their cause of death → `[R]`**: state the abandonment reason `basis` and the hop block `review_cond` (重审条件: unless which premise changes, this is not reopened), preventing the next session from re-proposing a rejected option.
4. **Full decision context of open questions → `[Q]`**: `statement` covers the open question and the list of sub-dimensions awaiting sign-off; the hop block `rationale / evidence_detail` records the known candidate directions, trade-offs, and risks.
5. **Macro-stage breakpoints and external deliverable artifacts → `[A]` + `artifacts` + `next_focus`**: whenever any track touches an external deliverable document (design record, plan, core spec, etc.), that `save` must attach it in `artifacts` (`name + path + note`, 0..n) and name the document in the item body/basis; mark unfinished stages `[~][A]` with the breakpoint stated.

**Four not-collect (guarantee high signal-to-noise; noise must never enter the ledger)**:
1. No fruitless intermediate exploration or trial-and-error logs (wrong-file hunts and transient-error reruns stay out; only the final verified conclusion is collected);
2. No superseded transitional phrasing within the session (collapse it in place via `td save --amend` within the same hop);
3. No in-session micro-execution steps (`todowrite` details, unit-test/lint fix loops, and Subagent internals must never enter `[A]`);
4. No full-body copies of external long documents (long texts already stored in `design.md / plan.md` are referenced by path via `artifacts` only).

### Topic granularity: three-way balance (anti-fragmentation & anti-topic-sticking)
1. **Cohesive evolution within the same topic (default main path: `td save [--amend]`)**: sub-problems, boundary fixes, implementation details, or incidental related increments that share the same final deliverable or the same system-change loop always stay inside the current topic (evolve via new/resolved `[Q]`, appended `[C]/[A]`). **Anti-fragmentation iron rule**: never create or fork a topic for a single sub-problem, a one-off bug fix, or a small local increment.
2. **Same-origin branch split (rare heavy operation: `td save --fork-as <new_id>`)**: both hard gates must hold — (1) strong background dependency (the branch must build on the current topic's settled `[C]/[R]` base); (2) an independent lifecycle (the branch becomes a phase-2 standalone project or a long-running parallel exploration, no longer accepted together with the main line; keeping it on the main line would block its closure or defocus `[Q]/[A]`). `--fork-as` copies the source `base_hop`'s four-track items (`op=inherit`) and seals the source hop, representing a one-way split that evolves independently (in the same hop's `mutations` you may `retract` original main-line open `[Q]/[A]` that do not belong to the branch; because `td merge` does not deduplicate shared ancestors by `origin`, forked branches never merge back via `td merge`).
3. **Alien-source hard switch to an independent new topic (anti-hodgepodge red line: `td match` → `td use`, or a new topic with `base_hop: null`)**: when a topic the user switches to mid-session shares neither a common deliverable nor any `[C]/[R]` background with the currently mounted topic, never write it into the current topic. First distill the original topic's unsaved increments (if any) with `td save`, then call `td match` for the new topic: on a hit, switch mounts with `td use`; on a miss, create an independent topic with `base_hop: null` and mark the new `topic_id` explicitly in the trailing `⚓ TopicDock:` line.
4. **After-the-fact correction**: if two windows mistakenly created two independent topics for the same subject, call `td merge <src_id> <dst_id>` to combine them; if the last 1-3 fork/consolidation/save steps were wrong, call `td undo` for one-step rollback.

### Subagent prohibition
- **Subagents MUST NEVER call `td match / save`**; distillation and retrieval are executed only by the top-level primary Agent.
- Never write in-session `todowrite`, plan mode, superpowers, or Subagent micro-steps into the action track `[A]` — TopicDock does not take over micro-execution loops.

### User manual Markdown edit prohibition
- `topics/<id>.md` and `hops/hop-NNN.md` may only be modified via `td` commands; any manual modification counts as **file corruption** — replayable corruptions are auto-repaired from `db + hops` (including 100% restoration of the title and artifact links from the latest hop's header snapshot), while unrepairable corruptions or a changed `topic_id` trigger cascade deletion. After manual edits, run `td doctor` immediately for self-healing.

### 5C desync absorption protocol (`STALE_BASE`, exit code 4)
- When another window has advanced (a new hop or an amend) and `(base_hop, base_sha)` is stale, `td save` returns a `STALE_BASE` payload and **never applies it silently**.
- `auto_absorbable: true` (`conflicts: []`, i.e. no overlap between this payload's changed items and those of the hops after base, and no header-field conflicts) → **re-send with the new base to absorb**: remount using the payload's `current_head` / `current_sha` (call `td use` to refresh the body if needed) and re-send the same payload with `base_hop: <current_head>`, `base_sha: <current_sha>`.
- `auto_absorbable: false` (`conflicts` non-empty, including the special case `reason: "BASE_SHA_MISMATCH_HEAD"` — the same head was amended by another window) → present the user a two-way choice:
  - **Fork**: `--fork-as <new_id>` forks a new topic from the state at base_hop (no overwrite risk);
  - **Overwrite**: `--force-merge` replays on top of the current head (last write wins; the response attaches `overwritten[]` listing overwritten items; if the payload references item ids that were overturned/retracted and have vanished → `INVALID_INPUT` + `vanished_items` list, exit code 7).
- `create` never constitutes a conflict; the conflict criteria are detailed in `references/cli-contract.md`, section STALE_BASE.

### Bootstrap onboarding (`UNINITIALIZED_STORE`, exit code 3)
- When neither the upward bubble search nor the global directory finds a store (all commands except `td init`), the primary Agent **asks the user once**: build the global unified store `~/.topicdock/` (default), a local store `<cwd>/.topicdock/`, or a custom path via `--path <dir>`; then call `td init --scope global|local [--path <dir>]` to initialize.

### Self-heal (heal) automatic handling summary
- Every command startup runs the seven-step self-heal under an exclusive lock (missing DB → cold rebuild → meta repair → crash adoption → wild-file cleanup → top-level md repair → referenced-hop classification → orphan-hop cleanup): repair when possible; unrepairable corruptions or a changed ID trigger cascade deletion — corrupted topics never block healthy ones.
- A missing `hop-NNN.md` = broken-link skip, no cascade (trace / view --history / delete annotate the missing hop); a missing external artifact file → same-name probing or a `[⚠️ 外部文件不存在，跳过读取]` warning, and save/doctor prunes dead links automatically.
- Inspection details and forced cold rebuild: `td doctor [--rebuild]`.
